# Git 주간 보고서 에이전트

로컬 Git 저장소의 커밋을 읽어 한 주 동안 바뀐 내용을 한국어 Markdown 보고서로 정리합니다. 각 요약에는 근거가 된 커밋 해시가 붙어 있어 원본 변경 사항을 확인할 수 있습니다. [주간 보고서 예시](examples/weekly-report.md)

## 실행

Python 3.10 이상, Git 2.37 이상, 로그인된 Codex CLI가 필요합니다. Codex CLI는 `codex exec`의 `--ignore-user-config`와 `--output-schema` 옵션을 지원해야 합니다. 개발 환경의 CLI 버전은 0.166.0입니다. 별도로 설치할 Python 패키지는 없습니다.

프로젝트 디렉터리에서 다음 명령을 실행하면 현재 저장소를 분석해 실행 디렉터리에 `weekly-report.md`를 작성합니다.

```shell
python weekly_agent.py --repo .
```

기본 기간은 로컬 날짜 기준으로 오늘을 포함한 최근 7일입니다. 지정한 저장소의 현재 `HEAD`에서 도달할 수 있는 커밋 중 커밋 시각이 이 기간에 해당하는 항목을 읽습니다.

```shell
python weekly_agent.py --repo ../my-project --start 2026-11-09 --end 2026-11-15 --output report.md
```

`--start`와 `--end`에는 시작일과 종료일을 `YYYY-MM-DD`로 입력하며 양쪽 날짜를 모두 포함합니다. `--output`은 결과 파일 경로를 지정합니다. 모델을 지정하려면 `--model` 뒤에 Codex 계정에서 사용할 수 있는 모델 이름을 입력하세요.

## 모델에 전달하는 데이터

에이전트는 최대 20개씩 커밋 번호, 날짜, 제목을 Codex에 전달합니다. 모델이 제목만으로 설명하기 어려운 커밋을 고르면, 에이전트는 해당 변경 내역(diff)을 커밋당 최대 4,000자까지 전달합니다. 여기에는 파일 경로와 소스 코드 일부가 포함될 수 있습니다. 에이전트는 모델이 반환한 번호에 누락이나 중복이 없는지 확인하고, 보고서에 실제 Git 해시를 붙입니다.

## KPI 측정

**KPI 예시** — Git 커밋 기반 주간 개발일지 작성 에이전트 1종을 GitHub에 등록하고, 실제 개발 기록으로 주간 보고서 3회를 생성합니다. 저장소 주소와 서로 다른 주차의 보고서 파일을 증빙으로 남길 수 있습니다.

각 요약의 근거는 `git show <해시>`로 확인할 수 있습니다. 작성 시간도 측정하려면 비슷한 커밋 수의 주차를 골라 수작업 시간과 에이전트 사용 시간을 비교하세요. 두 측정값 모두 최종 검토와 수정 시간을 포함합니다.
